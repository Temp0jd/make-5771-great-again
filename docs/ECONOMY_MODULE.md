# 经济模块（黑印监控与商店购买）— 未接入界面

状态：**仅引擎，未启用**。`src/economy.rs` 里是完整、已测试的规则逻辑，但界面**没有**任何入口，
`MacroProfile.economy` 也只会写入默认值。原因：商店流程还没设计好，先按你的要求把能力准备好，
之后接入界面时不需要再改规则。

## 已有能力

| 能力 | 说明 |
| --- | --- |
| 金币读数（半 OCR） | `CoinReader`：为 0–9 各配一张小模板 + 一个搜索区域；`decode_amount` 把识别到的数字框按 x 排序拼成数值，横向间距超过容差就结束，避免把旁边的图标算进来 |
| 商店条目 | `ShopEntry { name, price, priority, enabled }`，priority 越大越优先 |
| 购买策略 | `PurchasePolicy { reserve_gold, max_purchases, skip_unaffordable }`；`plan_purchases` 按优先级→价格排序，保证不花到保留线以下、不超过购买次数上限，买不起时按开关决定“跳过”还是“停止” |
| 变化检测 | `gold_changed(previous, current, threshold)`：金币变化达到阈值才触发后续动作，避免频繁干扰 |

## 还没有的部分（接入前需要补）

1. **读取时机与容错**：数字模板识别可能失败（背景遮挡、动画），需要“连续 N 次读数一致才采信”的确认策略。
2. **商店阶段判定**：怎么确认现在处于商店页面（复用现有的阶段标志模板）。
3. **价格读取**：现在 `ShopEntry.price` 是手填的固定价；如果要读货架价格，需要再加一组价格区域。
4. **购买动作**：点哪个货架格、确认按钮、售罄/买不起的处理，这些用现有步骤/分支即可编排，但需要先定流程。
5. **界面**：配置金币区域、录数字模板、维护商品列表与优先级、保留金币数与购买上限。

## 接入界面时的建议顺序

1. 先在「设置」加一个实验开关（默认关闭），把 `enabled` 接上；
2. 金币监控作为“视觉条件”的一种新类型接入（区域 + 数字模板 + 阈值），这样能复用现有的识别、稳定确认、失败恢复链路；
3. 商店购买做成一个子流程骨架（阶段标志 → 读金币 → `plan_purchases` → 逐个点击货架 → 确认），把决策交给 `plan_purchases`，点击交给现有步骤；
4. 先在你自己的流程里跑通，再决定是否做成通用预置。

> 注意：本模块不做任何内存/协议层读写，只依赖截图识别，和其余部分保持一致。
