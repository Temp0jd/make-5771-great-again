# 主流程 / 子流程与优先级选择框架（v0.7.0）

## 范围

这一版提供真实的数据、执行和编辑框架，不是商店/Buff 的预训练识别模型。仍采用现有 Rust 图像模板识别；不包含 OCR、余额/价格计算、商品库存判断、自动购买循环，也不监听并强行打断正在执行的主流程。

- 主流程：新增「调用子流程」步骤，按 ID 引用当前流程文件中的独立定义。
- 子流程库：创建、命名、独立增删/排序/编辑步骤。多个调用共享一份定义；更新一次即可生效。尚不提供跨流程文件的全局子流程库。
- 子流程正常完成后返回主流程下一步；失败或超时停止任务。暂不支持嵌套调用、递归、子流程结束本局或停止主流程。
- 保留专家默认显示，不恢复简洁模式切换入口。

## 设置商店购买

1. 在模板库截取商店标题、物品名称或独特图标、确认购买按钮、退出按钮。
2. 在「流程 → 子流程库」新建「商店购买」。
3. 添加「物品 / Buff 选择」，绑定商店阶段标志，检查阶段搜索范围。
4. 配置每个商品的候选区域（按流程参考分辨率，区域中心就是点击位置），区域不得重叠。
5. 添加规则并绑定物品模板。优先规则从上到下排序；禁止规则始终优先排除；允许随机规则在没有优先项时参与随机。
6. 后续添加普通识别点击步骤，确认购买成功、退出商店。执行器不会把“点击了购买”当作购买成功，需由后续图片识别验证。
7. 回主流程添加「调用子流程」，选择「商店购买」，把调用放在预期到达商店的位置。

## Buff 与数据不足时随机

Buff 使用同一选择步骤。没有足够模板时，可显式开启「数据不足时，允许从未识别的候选区域随机选择」。仍必须配置阶段标志和候选区域。

**未识别不等于允许。** 随机降级只能保证不点已识别为禁止/冲突的区域，不能保证未知候选不是禁选、空位、售罄或不可购买项。开启前必须确认所有声明的候选区域当前都可选。默认关闭，不在整个屏幕上随机点坐标。

阶段和候选识别需连续两次一致；点击前再次截取画面复核阶段与所选区域，并检查停止/前台状态。所有规则完整扫描后才决策，不用相似度分数替代用户优先级。命中多个身份的区域视为冲突，不参与随机。无可选项会重试至超时停止。

## 存储与兼容性

- `MacroProfile.subflows: [{id, name, steps}]`：旧文件缺省为空。
- `WorkflowStep.kind = CallSubflow`，`subflow_id` 指向定义。
- `WorkflowStep.kind = PrioritySelect`，`priority` 含 `stage_template`、`rules`、`slots`、`random_unknown`。
- 主流程和所有子流程的步骤 ID 全局唯一；分支内部 ID 仍属于各自步骤。
- 撤销/重做包含主流程和子流程。保存、模板引用统计/删除/重映射和分享包导出包含子流程依赖。
- 子流程中未引用的草稿可保持未绑定模板；执行预检仅检查启用调用可达的步骤（基础结构验证仍检查所有定义）。
- `.m5771pack` 仍是版本 1 容器。使用新步骤的包需要支持此框架的新程序；旧程序不认识新步骤种类，会拒绝加载，不能将其当作兼容旧程序的包分享。

## 示例与验证边界

`examples/modular-subflows-draft.m5771pack` 是可导入但**不可直接运行**的配置草稿：无图片资产，阶段模板及确认按钮需绑定，示例区域需按游戏画面重新核对。包含商店优先级和 Buff 未知随机两个独立子流程。

自动化覆盖：调用/返回顺序、停止与嵌套保护、全局 ID 与区域校验、优先/禁选/随机/冲突决策、完整扫描歧义检查、分享包路径往返和模板引用维护。Windows 游戏实机、DPI、多种商店布局以及真实购买成功率尚未验证。
